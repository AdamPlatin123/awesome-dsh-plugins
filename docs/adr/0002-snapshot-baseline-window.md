# 快照治理：并集基线固化 + 滚动窗口

全量清单（PLUGINS-ALL.md）的渲染语义依赖「全部历史快照的并集」——只在老快照出现过的仓库不能因窗口滚动而丢失（#189 登记轨兜底只覆盖已登记仓）。但快照每 1–2 小时 +1，无限增长会让仓库不可维护。决定：把既有全量快照的并集一次性固化为 data/snapshot-baseline.json；渲染器改为「baseline ⊕ 窗口内新快照」；清单仓删除 baseline 已覆盖的旧快照，仅保留最近约 30 天做审计回溯；此后每季度重固化一次 baseline。被否方案：直接改渲染窗口（丢未登记老仓的发现）；维持无限增长（远期迁移成本更高）。
